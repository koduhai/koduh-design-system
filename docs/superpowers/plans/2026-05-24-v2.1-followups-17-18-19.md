## Conventions every task follows (read once)

Read `CLAUDE.md` and the relevant reference files. Established patterns:

- **Folder shape:** `src/components/<Name>/` = `<Name>.tsx`, `<Name>.module.css`, `<Name>.test.tsx`, `<Name>.stories.tsx`, `index.ts`.
- **Data-attribute styling** (`.root[data-size='sm']`), never class composition. `cx(styles.root, className)` merges; `className` always forwarded to the root.
- **`--ku-*` CSS vars only**; inline custom properties (e.g. `style={{ '--grid-gap-base': 'var(--ku-space-4)' } as CSSProperties}`) bridge props → CSS — the `as CSSProperties` cast is **required** for `--*` keys.
- **`forwardRef` + spread DOM props**; mark components `/* @__PURE__ */`.
- **DOM-prop collisions must be `Omit`-ted** from extended HTMLAttributes (`size`, `value`, `onChange`, `defaultValue`, `color`, `title`) — #1 typecheck trap.
- **`noUncheckedIndexedAccess`**: `array[i]` is `T | undefined` — guard or `!` after a length check.
- **Vitest globals are NOT injected into tsconfig** — every test file must `import { describe, it, expect, vi } from 'vitest'` (and `beforeEach`/`beforeAll` as needed), or `npm run typecheck` fails even though `npx vitest run` passes.
- **`useRef<T>(null)` is typed `RefObject<T | null>`.**
- **Storybook `args` must satisfy required props** even when a `render` ignores them.
- **a11y:** WCAG AA is hard. Fix real axe failures (`link-in-text-block`, `landmark-unique`) in the component/story, never by disabling the rule. Repeated landmarks in a Showcase need distinct `aria-label`s.

### Shared type for responsive props (§3 — declare locally per component, do NOT create a shared module)

```ts
type Breakpoint = 'base' | 'sm' | 'md' | 'lg' | 'xl';
type ResponsiveValue<T> = T | Partial<Record<Breakpoint, T>>;
const BREAKPOINTS: Breakpoint[] = ['base', 'sm', 'md', 'lg', 'xl'];

/** Normalize a scalar-or-responsive prop to a breakpoint→value record. */
function toResponsive<T>(value: ResponsiveValue<T> | undefined): Partial<Record<Breakpoint, T>> {
  if (value == null) return {};
  if (typeof value === 'object' && !Array.isArray(value))
    return value as Partial<Record<Breakpoint, T>>;
  return { base: value as T };
}
```

(Grid's `columns` accepts `number | number[]`, so its `ResponsiveValue<number | number[]>` object branch must distinguish a breakpoint object from a `number[]` ratio — `Array.isArray` check above handles it: an array is treated as a scalar ratio at `base`.)

The breakpoint pixel values, hardcoded in every responsive `.module.css` (media queries can't read CSS vars), are the `--ku-breakpoint-*` token values: **sm 600px, md 900px, lg 1200px, xl 1536px**.

## Context-aware control recipe (read once — applied by Tasks 2–7)

Every context-aware control follows this exact pattern. `import { useOptionalFieldContext } from '../FormField';` then near the top of the component body:

```tsx
const field = useOptionalFieldContext();
// When inside a <FormField>, defer label/required/aria to it; otherwise use own props.
const id = field?.id ?? idProp ?? reactId; // reactId from existing useId(...)
const describedBy = field ? field.describedById : description != null ? descriptionId : undefined;
const invalid = field ? field.invalid : error;
const isRequired = field ? field.required : required;
const showOwnLabel = !field; // FormField renders the label when present
```

Then:

- Wrap the control's own `<label>` (and its required `*`) render in `{showOwnLabel && ( … )}` (for `Select`/`Combobox` which use a `<span id={labelId}>` "label", also gate it on `showOwnLabel`, and only set `aria-labelledby={labelId}` when `showOwnLabel`).
- Use `id` for the focusable element's `id`.
- Set `aria-invalid={invalid || undefined}`, `aria-describedby={describedBy}`, `required={isRequired}` on the focusable element.
- When `field` is present, do **not** render the control's own description/error `<p>` (FormField renders it). Gate that block on `showOwnLabel` too (i.e. `!field`).

**Type change for `TextField`/`Textarea`/`NumberField`:** change `label: ReactNode;` → `label?: ReactNode;` (optional). Document: "Provide `label`, or wrap the control in a `<FormField>` which supplies it."

Each task below gives the control's specific wiring points + tests. Tests use the standard `import { describe, it, expect, vi } from 'vitest'` line.
