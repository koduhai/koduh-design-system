# v2.1.0 Follow-ups — Issues #17 / #18 / #19 Design

**Date:** 2026-05-24
**Issues:** [#17](https://github.com/koduhai/koduhai-design-system-v2/issues/17) (form layer), [#18](https://github.com/koduhai/koduhai-design-system-v2/issues/18) (toast), [#19](https://github.com/koduhai/koduhai-design-system-v2/issues/19) (layout/typography). All surfaced dogfooding v2.1.0 in `koduh-console-demo`.

Three independent sections in one spec. All changes are **additive / non-breaking** unless explicitly noted. Conventions per `CLAUDE.md`: tokens → `--ku-*` CSS variables (never import token values), CSS Modules with data-attribute styling, `forwardRef` + spread DOM props, `cx(styles.root, className)`, `asChild` via `Slot`, controlled/uncontrolled via `useControllableState`, every public type exported from the component `index.ts` and re-exported from `src/index.ts`. WCAG AA is a hard requirement (axe e2e, dark + light).

**Out of scope:** the `useForm`/validation-orchestration engine (#17.2 — deferred to its own spec); DatePicker, FileUpload, multi-select Combobox, and remaining P2 items (tracked in #12).

## §1 — Form layer composition + gaps (#17)

### 1.1 Context-aware controls (the core bug) — HIGH

Today every shipped control self-renders its own `<label>`, required `*`, and `aria-invalid`/`aria-describedby`, and none read `FieldContext`. So `<FormField><TextField/></FormField>` double-renders the label and the FormField `<label htmlFor={id}>` targets the wrapper `<div>`, not the input.

**Fix:** add a non-throwing context reader and make the six controls consume it.

`src/components/FormField/useField.ts` gains:

```ts
/** Like useFieldContext, but returns null instead of throwing when there is no
 *  ancestor <FormField>. Lets a control opt into FormField composition while
 *  staying fully usable standalone. */
export function useOptionalFieldContext(): FieldContextValue | null {
  return useContext(FieldContext);
}
```

Each of **`TextField`, `Textarea`, `Select`, `NumberField`, `Combobox`, `TagInput`** calls `useOptionalFieldContext()`. When it returns a context (i.e. the control is inside a `FormField`):

- **Suppress** the control's own `<label>` and required `*` (FormField renders them).
- Use `field.id` for the control's `id` (so FormField's `<label htmlFor>` targets the focusable element).
- Set `aria-describedby = field.describedById`, `aria-invalid = field.invalid || undefined`, `required = field.required`.
- The control's own `label`/`error`/`errorText`/`helperText`/`required` props are ignored when context is present (context wins); document this precedence.

**`label` becomes optional** on the context-aware controls whose type currently requires it (`TextField`, `Textarea`, `NumberField`): inside a `FormField` the control omits `label` (FormField renders it). This is an additive type-loosening. Runtime contract: a control must have _either_ its own `label` _or_ an ancestor `FormField` — document it; standalone usage without either is the consumer's a11y responsibility (unchanged risk surface vs. today where label is required).

When there is **no** context, behavior is **exactly as today** (fully additive). FormField continues to work for arbitrary custom controls.

**Resulting usage:** `<FormField label="Email" required error errorText="Required"><TextField/></FormField>` → one visible label, correct `htmlFor`, error text + `aria-*` wired once.

**a11y note:** FormField currently renders `<label htmlFor={id}>`. For controls whose focusable element is not a native labelable element with that `id` (e.g. `Slider`'s thumb is a `<div role="slider">`), `htmlFor` won't associate. `Slider` is **not** in the context-aware set for this batch (it has no native input); it keeps its own `aria-labelledby`. The six controls above all expose a focusable element that takes `id` (native input, or the Select/Combobox trigger/input), so `htmlFor` resolves.

### 1.2 `onChange` shape consistency — MEDIUM (additive)

Standardize the _shape_ to `(value, event?)` without breaking changes:

- `Slider`: `onChange?: (value: number, event?: React.SyntheticEvent) => void` — add the optional `event` (was `(value)`). Non-breaking.
- `TagInput`: `onChange?: (tags: string[], event?: React.SyntheticEvent) => void` — add optional `event`. Non-breaking.
- `NumberField`: keeps `(value: number | null, event?)`. `null` is the honest "empty input" signal; **documented prominently** in the prop JSDoc and README form section rather than changed. (No `allowEmpty` prop — YAGNI.)
- `TextField`/`Textarea`/`Combobox`/`Select` already `(value, event)`.

### 1.3 Open the closed prop interfaces — MEDIUM

`ComboboxProps`, `TagInputProps`, `SliderProps` currently don't extend HTML attributes, blocking `onBlur`/`onFocus`/`name`/`data-*` from reaching the focusable element (needed to mark a field "touched").

- **`Combobox`**: `extends Omit<InputHTMLAttributes<HTMLInputElement>, 'value' | 'defaultValue' | 'onChange' | 'size'>`. Remaining props (incl. `onBlur`/`onFocus`/`name`/`data-*`) spread onto the `<input role="combobox">`.
- **`TagInput`**: `extends Omit<InputHTMLAttributes<HTMLInputElement>, 'value' | 'defaultValue' | 'onChange' | 'size'>`. Passthrough props (`onBlur`/`onFocus`/`name`/`data-*`) spread onto the inner text `<input>`; `className` stays on the field root.
- **`Slider`**: `extends Omit<HTMLAttributes<HTMLDivElement>, 'onChange' | 'defaultValue'>` on the root for `className`/`data-*`; additionally surface `onBlur`/`onFocus` forwarded to the **thumb** (`role="slider"`) so blur-touched works.

DOM-prop collisions must be `Omit`-ted (typecheck trap).

### 1.4 Minor gaps — LOW

- **`Combobox` `clearable`** (+ `clearLabel`, default `'Clear selection'`): shows a clear affordance when a value is selected; clearing resets value and reports `onChange('', event)` — mirrors `Select`. (Custom filtering already exists via the `filter` prop.)
- **`Slider`** gains the `error?` / `helperText?` / `errorText?` trio (rendered below the track like the other controls; `error` also reddens the track/description). Value readout stays via `formatValue` into the label.

## §2 — Toast enhancements (#18)

All additive on the existing module-singleton store + `<Toaster>`. Build on `src/components/Toaster/`.

### 2.1 `toast.promise()` — highest value

`useToast()`'s `toast` function gains:

```ts
toast.promise: <T>(
  promise: Promise<T>,
  msgs: {
    loading: ReactNode;
    success: ReactNode | ((value: T) => ReactNode);
    error: ReactNode | ((err: unknown) => ReactNode);
  },
  opts?: Omit<ToastOptions, 'severity' | 'description'>,
) => Promise<T>;
```

Behavior: enqueue a toast `{ severity: 'info', description: loading, duration: Infinity }`, capture its id; on resolve → `update(id, { severity: 'success', description: success(value), duration: <default> })`; on reject → `update(id, { severity: 'error', description: error(err), duration: <default> })`. Returns the original promise (so callers can `await`/chain). Resolves the loading→settled single-toast pattern.

### 2.2 Caller-supplied stable `id`

`ToastOptions` gains optional `id?: string`. In the store's `addToast`: if `options.id` is provided **and** a toast with that id already exists, **update it in place** (replace fields, keep position) instead of appending; otherwise insert with that id. If no `id`, generate one as today. This enables "Saving… → Saved" on a stable key and natural dedupe.

### 2.3 Dedupe

Falls out of 2.2: callers pass a stable `id` for actions that shouldn't stack (e.g. a toggle). Documented in the Toaster story + README. No separate description-hash dedupe.

### 2.4 Per-toast placement / multiple Toasters

`ToastOptions` gains optional `placement?: ToasterPlacement`. A toast's **effective placement** = `toast.placement ?? 'bottom-right'`. Each `<Toaster placement={P}>` renders **only** toasts whose effective placement === `P` (filter the snapshot in `Toaster.tsx`). Mounting multiple Toasters splits the stream (e.g. errors `top-center`, successes `bottom-right`); a single default `<Toaster>` shows all default-placement toasts as before. `max`/FIFO/pause-on-hover unchanged, applied per-Toaster after filtering. Documented.

### 2.5 Migration nit (docs)

Add a one-line callout: `const { toast } = useToast()` collides with a local `toast` state var common when migrating from Snackbar; alias it (`const { toast: showToast } = useToast()`).

## §3 — Layout / typography enhancements (#19)

### 3.1 Responsive props (object + ratio) on Grid/Stack/Inline — HIGH

Support, on `Grid` (`columns`, `gap`, `minItemWidth`) and `Stack`/`Inline` (`gap`):

- **Responsive object:** `columns={{ base: 1, md: 2 }}`, `gap={{ base: 3, md: 5 }}`. Keys are `base | sm | md | lg | xl` (the breakpoint scale; `base` = no media query).
- **Track ratio (Grid `columns` only):** `columns={[1.1, 1]}` → `grid-template-columns: 1.1fr 1fr`. May itself be responsive: `columns={{ base: [1], md: [1.1, 1] }}`.

**Zero-runtime mechanism (important):** the component resolves each prop into per-breakpoint inline **CSS custom properties** (e.g. `--grid-cols-base`, `--grid-cols-md`, `--grid-gap-md`), emitting only the breakpoints the consumer supplied. The `.module.css` carries **static** media queries at the literal token pixel values — `@media (min-width: 600px)` (sm), `900px` (md), `1200px` (lg), `1536px` (xl) — each of which, when the matching var is set, overrides `grid-template-columns`/`gap` from that var. Media queries cannot read CSS variables for their conditions, so the breakpoints are hardcoded in CSS to the `--ku-breakpoint-*` values (documented as the single source kept in sync with `tokens.ts`).

A scalar value (`columns={3}`, `gap={4}`) keeps working — it sets only the `base` var. A small shared helper (per component, not a shared module) normalizes `T | ResponsiveValue<T>` → a record of breakpoint→value.

```ts
type Breakpoint = 'base' | 'sm' | 'md' | 'lg' | 'xl';
type ResponsiveValue<T> = T | Partial<Record<Breakpoint, T>>;
```

### 3.2 `Text` / `Heading` `leading` — HIGH

`leading?: 'tight' | 'normal' | 'relaxed'` → `--ku-line-height-{tight|base|relaxed}` (`normal` → `base`). Data-attribute styled. `Text` default unchanged (`base`); `Heading` default `tight`.

### 3.3 `Text` typographic escape hatches — MEDIUM

Add to `Text`:

- `family?: 'base' | 'mono'` → `--ku-font-family-{base,mono}`.
- `numeric?: 'normal' | 'tabular'` → `font-variant-numeric: tabular-nums` when `'tabular'`.
- `transform?: 'none' | 'uppercase' | 'lowercase' | 'capitalize'`.
- `truncate?: boolean` → single-line `overflow:hidden; text-overflow:ellipsis; white-space:nowrap`.
- `lineClamp?: number` → multi-line clamp (`-webkit-line-clamp` + `display:-webkit-box`); mutually exclusive with `truncate` (truncate wins if both). Emit `--text-line-clamp` inline.

All data-attribute / custom-property styled.

### 3.4 `Box` — MEDIUM (new component)

A focused escape hatch — **curated** props, not arbitrary style passthrough:

```ts
interface BoxProps extends HTMLAttributes<HTMLDivElement> {
  padding?: SpaceToken; // all sides
  px?: SpaceToken; // inline padding (overrides padding on x)
  py?: SpaceToken; // block padding (overrides padding on y)
  grow?: boolean; // flex-grow: 1
  shrink?: boolean; // flex-shrink: 1 (default browser is 1; false → 0)
  minWidth?: 0 | string; // common min-width:0 for flex children
  width?: string;
  as?: ElementType; // default 'div'
  asChild?: boolean;
}
```

Padding/space props map to `--ku-space-*` via inline custom properties consumed by the module CSS. `grow`/`shrink` are data-attributes. Solves equal-height cards, footers pinned with `grow`, and `min-width:0` flex children.

### 3.5 `DescriptionList` — MEDIUM (new component)

```ts
interface DescriptionItem {
  term: ReactNode;
  description: ReactNode;
}
interface DescriptionListProps extends HTMLAttributes<HTMLDListElement> {
  items: DescriptionItem[];
  /** Fixed width of the term (label) column. Defaults to 'max-content'. */
  termWidth?: string;
  /** Row gap (space token). Defaults to 3. */
  gap?: SpaceToken;
}
```

Renders a `<dl>` as a 2-track CSS grid: `grid-template-columns: <termWidth> 1fr`, each item a `<dt>` + `<dd>`. Term styled muted/secondary; description primary. Replaces the hand-rolled key-value `<dl>`s.

### 3.6 Small additions — LOW

- `Stack`/`Inline` `align` gains `'baseline'` (→ `align-items: baseline`).
- `Stack`/`Inline` gain an `as?: ElementType` prop (consistency with `Text`; e.g. an AppBar actions slot wanting `<span>`). `asChild` still supported; `as` ignored when `asChild`.
- `Container` gains `py?: SpaceToken` (vertical padding; `padded` still controls horizontal). Optionally `padding?: SpaceToken` for all-sides — include `py` only to stay minimal.

## §4 — Build mechanics & integration

Per the established parallel workflow. Independent work-streams → parallel subagents where folders don't overlap:

- **§1.1 context-awareness** touches 6 existing control folders + adds `useOptionalFieldContext` to `FormField`. The `FormField` export change lands first (tiny), then the 6 control edits are independent folders (parallel).
- **§1.2–1.4** fold into those same 6 control edits (Slider/Combobox/TagInput get the interface + onChange + minor-gap changes; do them together per folder).
- **§2 Toaster** — one folder, one stream.
- **§3** — `Grid`/`Stack`/`Inline` (responsive + small props), `Text`/`Heading` (typographic props), `Container` (py), plus new `Box` and `DescriptionList` folders — independent, parallel.

**Integration session** (main): wire `src/index.ts` (new `Box`, `DescriptionList`, `useOptionalFieldContext`, new types), e2e `COMPONENTS` (Box, DescriptionList showcases; add responsive + FormField-composition stories), update README + MIGRATION + CLAUDE.md component count, run the FULL gate (typecheck/lint/test/build/verify:bundle/verify:exports/e2e axe+visual dark+light), regenerate Linux baselines via `update-baselines.yml`, PR → CI green → merge → release (minor bump → **2.2.0**, CHANGELOG, GitHub Release triggers publish), close #17/#18/#19 (each with its own `closes` keyword). #12 stays open.

**Known traps** (from prior phases): vitest test files need explicit `import { describe, it, expect, vi } from 'vitest'` (tsconfig doesn't inject globals); `useRef<T>(null)` is `RefObject<T | null>`; Storybook `args` must satisfy required props even with a custom `render`; `noUncheckedIndexedAccess` makes array access `T | undefined`; `--ku-*` inline styles need `as CSSProperties`; new stories need committed `*-linux.png` baselines (the bot baseline-commit push doesn't auto-trigger CI → close/reopen the PR to re-run); axe `link-in-text-block` and `landmark-unique` get fixed in the component/story, never by disabling the rule.

**Testing:** each control's context-awareness gets a unit test wrapping it in `<FormField>` asserting single label + `htmlFor` targeting the focusable element + aria sourced from context, and a standalone test confirming unchanged behavior. Toast `promise`/`id`-update/`placement`-filter get store + render tests (fake timers). Responsive props get tests asserting the emitted custom properties per breakpoint. New components (Box, DescriptionList) get the standard folder test + Showcase story.
